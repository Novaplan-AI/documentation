## Überblick

Der ServiceNow-Konnektor synchronisiert Wissensdatenbanken, Kategorien, Artikel und Anhänge für die Suche in Novaplan AI. Er übernimmt außerdem Benutzer- und Gruppenkontext, der für Sichtbarkeit und Berechtigungen relevant ist. Die Verbindung verwendet **OAuth 2.0**.

| Inhalt | Verwendung |
| --- | --- |
| Wissensdatenbanken und Kategorien | Struktur der Wissensinhalte |
| Artikel und Anhänge | Durchsuchbarer Inhalt |
| Benutzer und Gruppen | Berechtigungskontext und Sichtbarkeit |

Für die Einrichtung brauchen Sie Zugriff auf **Application Registry** in ServiceNow und die nötigen Rollen für die betreffenden Wissensdatenbanken. Novaplan unterstützt Sie bei der Konfiguration. Testen Sie die Verbindung zunächst mit einer nicht produktiven Instanz, wenn Ihre ServiceNow-Richtlinien das vorsehen.

## OAuth-Anwendung vorbereiten

1. Öffnen Sie in Novaplan AI **Workspace Settings → Connectors**, suchen Sie **ServiceNow** und wählen Sie **+ Setup**.
2. Geben Sie unter **Authenticate Instance** einen **Instance name** ein.
3. Kopieren Sie die dort angezeigte **Redirect URL**. Verwenden Sie genau diesen Wert in ServiceNow, einschließlich Schema (`https`), Host, Pfad und möglichem abschließenden Schrägstrich. Erfinden oder übernehmen Sie keine Callback-URL aus einem Beispiel.
4. Melden Sie sich mit den nötigen Administrationsrechten in ServiceNow an. Öffnen Sie **System OAuth → Application Registry**, wählen Sie **New** und dann **Create an OAuth API endpoint for external clients**.
5. Vergeben Sie einen Namen wie `Novaplan AI KB Connector` und tragen Sie die kopierte **Redirect URL** ein. ServiceNow erzeugt **Client ID** und **Client Secret**. Bewahren Sie das Secret sicher auf.
6. Prüfen Sie **Accessible from** und die Laufzeit des Refresh-Tokens gemäß Ihrer ServiceNow-Sicherheitsrichtlinie. Die Quellanleitung nennt **All application scopes** und `8640000` Sekunden (rund 100 Tage) als Beispiele, nicht als allgemeine Vorgabe.
7. Speichern Sie die OAuth-Anwendung.

<Warning>
  Änderungen an **Client ID**, **Client Secret** oder **Redirect URL** müssen in Novaplan AI nachgezogen werden. Danach ist eine neue Autorisierung erforderlich.
</Warning>

## ServiceNow in Novaplan AI autorisieren

Prüfen Sie vorab, ob das für **Authorize** verwendete ServiceNow-Konto Zugriff auf die gewünschten Wissensinhalte hat. Je nach Ihrer Instanz können dafür Administrations- oder Impersonationsrechte erforderlich sein; die konkreten Rollen und ACLs muss Ihre ServiceNow-Administration festlegen. Die Quellanleitung empfiehlt für dieses Konto dieselbe E-Mail-Adresse wie im zugeordneten Novaplan-AI-Konto, damit Berechtigungen korrekt zugeordnet werden.

1. Ergänzen Sie unter **Authenticate Instance** die OAuth-Zugangsdaten. Wählen Sie eine bereits gespeicherte **OAuth app**, falls Ihr Workspace sie anbietet, oder tragen Sie **Client ID** und **Client Secret** ein.
2. Verwenden Sie für die drei Endpunkte den Host Ihrer eigenen Instanz, ohne abschließenden Schrägstrich bei der Instanz-URL:

   | Feld | Schema |
   | --- | --- |
   | **ServiceNow Instance URL** | `https://your-instance.service-now.com` |
   | **ServiceNow Authorize URL** | `https://your-instance.service-now.com/oauth_auth.do` |
   | **ServiceNow Token URL** | `https://your-instance.service-now.com/oauth_token.do` |

3. Vergleichen Sie die **Redirect URL** erneut mit dem Eintrag in ServiceNow und wählen Sie **Next**.
4. Wählen Sie auf **Authorize** **Authenticate ServiceNow to Proceed** und schließen Sie Anmeldung und Freigabe im ServiceNow-Fenster ab.
5. Erst nach erfolgreicher Anmeldung wird **Continue to configuration** verfügbar. Wechseln Sie damit zu **Configure Records**.

## Synchronisierung festlegen

Wählen Sie unter **Configure Records** eine **Sync strategy**, zum Beispiel **Scheduled** oder **Manual**. Bei einem Zeitplan legen Sie das **Sync interval** fest; die Quellanleitung verwendet eine Stunde als Beispiel. Speichern Sie mit **Save Configuration** und wählen Sie anschließend **Start Syncing Now** oder **I'll do it later**. Prüfen Sie den Status auf der ServiceNow-Instanzkarte.

Die erste Synchronisierung liest Benutzer, Gruppen, Wissensdatenbanken, Kategorien und Artikel im eingerichteten Umfang. Spätere Läufe können Änderungen anhand von Feldern wie `sys_updated_on` erkennen. Die Dauer hängt von Anzahl der Artikel, Kategorien, Benutzer und Anhänge ab. Prüfen Sie nach dem ersten Lauf die Sichtbarkeit mit geeigneten Testkonten; die Quellanleitung beschreibt die Beachtung von ServiceNow-ACLs und Wissensdatenbankrechten, deren tatsächliche Wirkung von Ihrer Instanzkonfiguration abhängt.

## Fehler beheben

| Problem | Prüfen Sie |
| --- | --- |
| Ungültige Client-Zugangsdaten | **Client ID**, **Client Secret**, aktive OAuth-Anwendung und mögliche Rotation |
| Callback wird abgewiesen | Zeichengetreue Übereinstimmung der **Redirect URL** in beiden Systemen |
| Autorisierung schlägt fehl | ServiceNow-Konto, Kontostatus, Rollen und Zugriff auf die konfigurierte Instanz |
| Token läuft ab oder Synchronisierung stoppt | Refresh-Token-Laufzeit; bei Widerruf oder Rotation erneut autorisieren |
| Artikel fehlen | Knowledge-Base-Rechte, Tabellen-ACLs, Gruppenmitgliedschaft, Synchronisierung und Indexierung |
| Datensätze unter **All Records**, aber keine Suchtreffer | Abschluss der Indexierung und Konfiguration unter **Configure Records** |

Bei strengeren OAuth- oder SSO-Richtlinien sollten Ihre ServiceNow-Administration und [Novaplan Support](/de/contact-us) die Einrichtung gemeinsam prüfen. Die jeweils gültige Callback-URL finden Sie im Konnektordialog Ihres Workspaces.
