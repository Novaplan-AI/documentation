[Omnigent](https://omnigent.ai) kann entfernte MCP-Server einbinden. Für den Zugriff auf Novaplan AI verwenden Sie ein **persönliches Zugriffstoken** der jeweiligen Person, damit Ergebnisse deren Berechtigungen beachten. Teilen Sie kein Token im Team. Der [MCP-Überblick](/de/mcp/overview) erklärt den Workspace-Endpunkt.

<Note>
  Für diese Verbindung wird ein `Authorization: Bearer`-Header verwendet. Der dokumentierte Browser-OAuth-Weg von Omnigent setzt eine dynamische Client-Registrierung voraus, die für Novaplan AI hier nicht bestätigt ist. Andere Clients wie Cursor oder Claude Code verwenden eine vorab registrierte OAuth-Anwendung.
</Note>

## Voraussetzungen

- Ein erreichbarer Novaplan AI Workspace mit indexierten Inhalten und MCP-Zugriff.
- Ein eigenes Token aus **Workspace-settings → Developer Settings → Personal Access Tokens**. Der Wert wird nur einmal angezeigt; kopieren Sie ihn sofort und bewahren Sie ihn sicher auf.
- Eine installierte Omnigent-Umgebung und Zugang zu dem Modell, das Ihr Agent verwendet.

## Verbindung für eine Sitzung

1. Öffnen Sie in Omnigent für die Sitzung **Agent info → Manage MCP servers**.
2. Fügen Sie `NOVAPLAN_WORKSPACE_URL/mcp` als URL hinzu. Setzen Sie den Header `Authorization: Bearer <IHR_TOKEN>` mit Ihrem eigenen Token.
3. Starten Sie die Sitzung neu und stellen Sie eine Frage, deren Antwort nur in Ihren Unternehmensdaten steht. Prüfen Sie die Quellenangaben.

## Konfiguration für einen Agenten

Omnigent kann Umgebungsvariablen in URL und Header einsetzen. Eine Beispiel-Datei `tools/mcp/novaplan.yaml` enthält dadurch keine geheimen Werte:

```yaml
name: novaplan
description: Suche in freigegebenem Unternehmenswissen.
transport: http
url: ${NOVAPLAN_MCP_URL}
headers:
  Authorization: "Bearer ${NOVAPLAN_MCP_TOKEN}"
```

Setzen Sie `NOVAPLAN_MCP_URL` auf die vollständige `/mcp`-Adresse und `NOVAPLAN_MCP_TOKEN` auf Ihr persönliches Token in der geschützten Laufzeitumgebung. Die URL-Interpolation setzt laut Omnigent-Anleitung Version 0.10.0 oder neuer voraus. Prüfen Sie bei älteren Versionen die tatsächliche Unterstützung, statt Secrets in ein Repository zu schreiben.

Ergänzen Sie in den Agentenanweisungen, dass der Agent bei internen Fragen zuerst sucht, Quellen zitiert, fehlende Treffer offen benennt und Fehler der MCP-Verbindung meldet. Sonst kann ein fehlgeschlagener Tool-Aufruf wie eine normale Antwort aus Modellwissen aussehen.

## Geeignete Werkzeuge

Die [Werkzeugreferenz](/de/mcp/tools) beschreibt alle dokumentierten Argumente. Die aktuellen technischen Kennungen `pipeshub_chat`, `pipeshub_search` und `pipeshub_get_record_content` stehen für Antworten über mehrere Dokumente, das Finden einer bestimmten Datei und das vollständige Lesen eines Datensatzes. Die Namen müssen vor Veröffentlichung mit dem bereitgestellten Novaplan MCP-Server abgeglichen werden.

Wenn alle Aufrufe `401` zurückgeben, prüfen Sie Ablauf, Widerruf und Scope des Tokens sowie die Workspace-Adresse. Ändern oder kürzen Sie den Tokenwert nicht aufgrund eines Beispielbefehls. Für Hintergrundprozesse ohne Benutzerkontext kann ein Anwendungs-Token nur an ausdrücklich freigegebenen Endpunkten geeignet sein; für Antworten mit persönlichen Quellberechtigungen bleibt eine benutzergebundene Anmeldung erforderlich. Bei Fragen hilft [Novaplan Support](/de/contact-us).
