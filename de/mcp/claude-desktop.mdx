Claude Desktop kann einen Novaplan AI Workspace auf zwei Wegen erreichen. Für einen öffentlich erreichbaren HTTPS-Workspace verwenden Sie einen **Custom Connector** mit persönlicher OAuth-Anmeldung. Bei einem internen Workspace kann eine lokale Stdio-Brücke infrage kommen; dafür muss Novaplan die verwendete Paketversion und den Zugang freigeben.

## Custom Connector für einen HTTPS-Workspace

1. Lassen Sie eine [OAuth-Anwendung](/de/mcp/overview#schritt-1-oauth-anwendung-erstellen) für den Workspace einrichten und sichern Sie **Client ID** und **Client Secret**.
2. Öffnen Sie in Claude Desktop **Settings → Connectors → Add custom connector**.
3. Tragen Sie `NOVAPLAN_WORKSPACE_URL/mcp` als Serveradresse ein. Verwenden Sie die von Novaplan bestätigte HTTPS-Adresse.
4. Öffnen Sie **Advanced settings** und tragen Sie Client ID und Client Secret ein.
5. Wählen Sie **Add**, melden Sie sich persönlich im Browser an und prüfen Sie die angeforderten Berechtigungen.

Hinterlegen Sie in der Novaplan-OAuth-Anwendung die Redirect URI `https://claude.ai/api/mcp/auth_callback`. Ein Custom Connector kann eine interne `localhost`-Adresse oder einen privaten Hostnamen nicht über das öffentliche Connector-Verfahren erreichen.

## Lokale Stdio-Brücke für interne Workspaces

Die bestehende technische Brücke verwendet das npm-Paket `@pipeshub-ai/mcp`. Dieser Paketname ist eine **funktionale Kennung**, für die kein bestätigtes Novaplan-Paket vorliegt. Verwenden Sie diese Variante erst, wenn Novaplan sie für Ihren Enterprise Workspace freigegeben hat.

<Warning>
  Suchen und Antworten mit persönlichen Quellberechtigungen benötigen eine **benutzergebundene** Anmeldung. Ein OAuth-`client_credentials`-Token besitzt keine Benutzeridentität und ist dafür nicht geeignet. Nutzen Sie bei der geprüften Brücke ein persönliches Zugriffstoken mit `--bearer-auth`; geben Sie es niemals in einer gemeinsam genutzten Konfiguration oder einem Repository weiter.
</Warning>

Die technische Konfiguration von Claude Desktop liegt in `claude_desktop_config.json`. Ein Beispiel mit Platzhaltern:

```json
{
  "mcpServers": {
    "novaplan": {
      "command": "npx",
      "args": [
        "-y", "@pipeshub-ai/mcp", "start",
        "--server-url", "NOVAPLAN_WORKSPACE_URL",
        "--bearer-auth", "YOUR_BEARER_TOKEN"
      ]
    }
  }
}
```

`novaplan` ist nur der lokale Servername; der Paketname muss dem tatsächlich installierten Paket entsprechen. Nach dem Bearbeiten muss Claude Desktop vollständig beendet und erneut geöffnet werden. Die [Stdio-Referenz](/de/mcp/local-server) enthält weitere Client-Beispiele.

Bei Verbindungsfehlern prüfen Sie zuerst die Erreichbarkeit der Workspace-Adresse und die OAuth-Redirect-URI beziehungsweise das persönliche Token. Wenn die Brücke nicht startet, prüfen Sie Node.js und `npx`. Für die Bestätigung der unterstützten Paketversion und des Zugriffs hilft [Novaplan Support](/de/contact-us).
