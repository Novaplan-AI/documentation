# OpenAI-kompatible API konfigurieren

![Konfigurationsansicht für OpenAI-kompatible APIs](/images/ai-models/llm/OpenAICompatible_LLMConfig.png)

Diese Anbieteroption verbindet Novaplan AI mit einem Dienst, dessen API das OpenAI-Format für Chat-Anfragen unterstützt. Dazu können externe Modellplattformen oder ein von Ihrer Organisation betriebener Dienst gehören. Novaplan unterstützt Sie bei der Einrichtung; prüfen Sie vorab, welche Endpunkte und Funktionen der gewählte Dienst tatsächlich anbietet.

## Erforderliche Angaben

| Feld | Bedeutung |
| --- | --- |
| **Endpoint URL** | Vom gewählten Anbieter dokumentierte API-Basisadresse. Viele Anbieter verwenden `/v1/`, etwa `https://api.together.xyz/v1/` oder `https://openrouter.ai/api/v1/`; DeepSeek dokumentiert derzeit `https://api.deepseek.com` ohne dieses Suffix. Novaplan AI ergänzt die benötigten Pfade für Aufrufe. Lassen Sie die Verbindung aus dem verwalteten Workspace prüfen. |
| **API Key** | Schlüssel des gewählten Anbieters. Erstellen Sie ihn im Konto oder in den Einstellungen des Dienstes und bewahren Sie ihn geschützt auf. |
| **Model Name** | Genaue Modell-ID aus dem Katalog des Anbieters, beispielsweise `deepseek-ai/DeepSeek-V3`. |

Die Modell-ID muss exakt zur Bezeichnung beim Anbieter passen. Prüfen Sie dabei Kontextlänge, Funktionen, Verfügbarkeit und Kosten. Ein Endpoint, der nur einen Teil des OpenAI-API-Formats umsetzt, kann bei bestimmten Anfragen fehlschlagen.

## Optionale Funktionen

- **Multimodal:** Nur einschalten, wenn das ausgewählte Modell Bildeingaben unterstützt und Sie solche Inhalte verarbeiten möchten.
- **Reasoning:** Nur einschalten, wenn das Modell einen entsprechenden Modus anbietet. Dieser kann andere Antwortzeiten und Kosten haben.

## Modell hinzufügen

1. Wählen Sie als **Provider Type** die Option **OpenAI API Compatible**.
2. Tragen Sie **Endpoint URL**, **API Key** und **Model Name** ein.
3. Aktivieren Sie **Multimodal** oder **Reasoning** nur bei bestätigter Modellunterstützung.
4. Klicken Sie auf **Add Model**.

Endpoint URL, API Key und Model Name sind erforderlich. Prüfen Sie bei Verbindungsproblemen die vom Anbieter dokumentierte Basisadresse, HTTPS und die Erreichbarkeit aus der Novaplan-Umgebung. Ergänzen Sie `/v1/` nur, wenn der gewählte Anbieter es verlangt. Bei Authentifizierungsfehlern kontrollieren Sie Schlüssel und Berechtigungen. Bei **Model not found** vergleichen Sie die ID mit dem Modellkatalog und dem Zugang Ihres Kontos. Quoten und Abrechnung richten sich nach dem Anbieter; [Novaplan Support](/de/contact-us) hilft bei der Verbindung.
