Der E-Mail-Dienst versendet Nachrichten für Anmeldung, Passwortzurücksetzung, Kontenerstellung, Einladungen und Sicherheitsmeldungen. Novaplan richtet den SMTP-Versand für den Kunden-Workspace ein. Die [SMTP-Anleitung](/de/smtp) beschreibt die administrativen Einstellungen; diese Seite dokumentiert die internen API-Abläufe.

<Warning>
  Die folgenden Endpunkte und Token-Scopes stammen aus der technischen Referenz. Prüfen Sie vor produktiver Nutzung, ob sie im Novaplan Enterprise Workspace freigegeben sind. Verwenden Sie keine administrativen SMTP-Endpunkte in einer Kundenanwendung ohne ausdrückliche Freigabe.
</Warning>

## Authentifizierung und Vorlagen

Alle hier beschriebenen Endpunkte beginnen mit `/api/v1` und erwarten einen Bearer-Token. Die Referenz nennt `SEND_MAIL` für das Versenden und `FETCH_CONFIG` für das Aktualisieren der geladenen SMTP-Konfiguration. Diese Namen sind technische Kennungen und dürfen nur nach Prüfung des bereitgestellten Dienstes geändert werden.

Im zugänglichen Quellcode sind `loginWithOTP`, `resetPassword`, `resetEmail`, `accountCreation`, `orgEmailVerification`, `appuserInvite`, `suspiciousLoginAttempt` und `domainLimitReached` als Vorlagentypen registriert. Die Variable `templateData` enthält die zur Vorlage passenden Werte, etwa `userName`, `companyName`, `otp`, `resetLink` oder `inviteLink`. Prüfen Sie vor einer Integration, welche Vorlagen im bereitgestellten Enterprise-Dienst verfügbar sind.

## Nachricht versenden

**`POST /api/v1/mail/emails/sendEmail`** erwartet laut Referenz einen Token mit `SEND_MAIL` und folgende Felder:

| Feld | Pflicht | Bedeutung |
| --- | --- | --- |
| `emailTemplateType` | Ja | Einer der unterstützten Vorlagentypen |
| `sendEmailTo` | Ja | Liste der Empfängeradressen |
| `subject` | Ja | Betreff |
| `templateData` | Ja | Variablen für die gewählte Vorlage |
| `sendCcTo` | Nein | CC-Empfänger |
| `attachments` | Nein | An Nodemailer übergebene Anhangobjekte; Binärkodierung prüfen |
| `fromEmailDomain` | Nein | Metadatenfeld; im geprüften Code kein Override des SMTP-Absenders |
| `productName` | Nein | Feld im Request-Typ; der geprüfte Versandpfad verwendet es nicht direkt |
| `isAutoEmail` | Nein | Feld im Request-Typ; der geprüfte Versandpfad verwendet es nicht direkt |

Ein Beispiel ohne echte Zugangsdaten:

```json
{
  "emailTemplateType": "appuserInvite",
  "sendEmailTo": ["user@example.com"],
  "subject": "Einladung zu Novaplan AI",
  "templateData": {
    "userName": "Erika Beispiel",
    "companyName": "Beispiel GmbH",
    "inviteLink": "https://workspace.example.com/invite/example"
  }
}
```

Die optionale Liste `attachments` wird an Nodemailer weitergegeben. Für einen als Base64-Zeichenfolge übertragenen Anhang geben Sie laut [Nodemailer-Referenz](https://nodemailer.com/message/attachments) `encoding: "base64"` an. Dieses Beispiel enthält den Text „Hello“ als `note.txt`:

```json
{
  "filename": "note.txt",
  "content": "SGVsbG8=",
  "encoding": "base64",
  "contentType": "text/plain"
}
```

Prüfen Sie, ob der bereitgestellte Enterprise-Endpunkt dieses Anhangsformat akzeptiert. Für Kopien verwenden Sie `sendCcTo`; der geprüfte Request-Typ enthält kein BCC-Feld. Der SMTP-Absender stammt aus der Konfiguration `fromEmail`, nicht aus `fromEmailDomain`. Der Vorlagentyp bestimmt, welche Felder in `templateData` benötigt werden: `otp` für den Einmalcode, `resetLink` für die Passwortzurücksetzung und `inviteLink` für Einladungen.

Bei Erfolg antwortet der Endpunkt laut technischer Referenz mit **`200 OK`** und einem Ergebnis wie diesem:

```json
{
  "data": {
    "status": true,
    "data": "Email sent"
  }
}
```

Nach erfolgreichem Versand wird in MongoDB ein Datensatz mit Betreff, Absender, Empfänger- und CC-Liste, Vorlagentyp und Zeitstempeln gespeichert. Die Antwort bestätigt den Versandversuch über den konfigurierten SMTP-Anbieter; sie ist keine Zustellbestätigung des empfangenden Postfachs.

| HTTP-Status | Antwort aus der Referenz | Mögliche Ursache |
| --- | --- | --- |
| `400` | `Unknown Template` | `emailTemplateType` ist kein unterstützter Vorlagentyp. |
| `400` | `Smtp not configured properly` | Erforderliche SMTP-Angaben fehlen oder sind ungültig. |
| `401` | `Authorization header not found` | Der Bearer-Header fehlt. |
| `403` | `Invalid token scope` | Dem Token fehlt `SEND_MAIL`. |
| `404` | `Smtp Configuration not set` | Es wurde keine SMTP-Konfiguration geladen. |
| `500` | `Error sending mail` | Versand über den SMTP-Anbieter ist fehlgeschlagen. |

## SMTP-Konfiguration neu laden

**`POST /api/v1/mail/updateSmtpConfig`** lädt die zuvor im Configuration Manager gespeicherten SMTP-Einstellungen neu. Laut Referenz benötigt der Aufruf `FETCH_CONFIG` und keinen Request-Body. Die Konfiguration umfasst Host, Port, Standard-Absenderadresse und gegebenenfalls SMTP-Benutzername und -Passwort. Ein Passwort wird in der Antwort nicht zurückgegeben.

Der Dienst prüft vor einem Versand, ob die notwendigen SMTP-Felder vorhanden sind. Vorlagen werden verarbeitet und anschließend über den konfigurierten SMTP-Anbieter verschickt. Bei Zustellfehlern prüfen Sie zuerst die Workspace-Konfiguration und den SMTP-Anbieter; [Novaplan Support](/de/contact-us) kann die serverseitigen Protokolle prüfen.

Die SMTP-Konfiguration umfasst `host`, `port` (in der Referenz standardmäßig **587**), `fromEmail` sowie optional `username` und `password`. Der Endpunkt zum Neuladen antwortet bei Erfolg mit **`200 OK`**, einer Meldung und den nicht vertraulichen Einstellungen. Das Passwort wird nicht zurückgegeben. Bei fehlendem Bearer-Header, unzureichendem `FETCH_CONFIG`-Scope oder fehlendem Mail-Container nennt die Referenz `401`, `403` beziehungsweise `404`.

## Datenmodelle

| Modell | Wichtige Felder |
| --- | --- |
| `MailInfo` | `orgId`, `subject`, `from`, `to[]`, optional `cc[]`, `emailTemplateType`, `createdAt`, `updatedAt` |
| `MailBody` | `emailTemplateType`, `sendEmailTo[]`, `subject`, `templateData`; optional `sendCcTo[]`, `attachments[]`, `productName`, `isAutoEmail`, `fromEmailDomain` |
| `SmtpConfig` | `host`, `port`, `fromEmail`; optional `username` und `password` |
| `MailConfig` | JWT-Schlüssel, MongoDB-Verbindungsdaten und die SMTP-Konfiguration |

Die Vorlagentypen sind technische Werte, darunter `loginWithOTP`, `resetPassword`, `resetEmail`, `accountCreation`, `orgEmailVerification`, `appuserInvite`, `suspiciousLoginAttempt` und `domainLimitReached`. Ändern Sie diese Werte nicht für eine Übersetzung der sichtbaren E-Mail-Texte.

## Verarbeitung und Sicherheit

Vor dem Versand prüft der Dienst das JWT, den benötigten Scope und die SMTP-Konfiguration. Er wählt die passende Handlebars-Vorlage, setzt die Werte aus `templateData` ein und ergänzt Layout, wiederverwendbare Kopf- und Fußbereiche sowie responsives Styling. Danach setzt er Absender, Empfänger, Kopien und Anhänge, versendet die Nachricht über SMTP und speichert die Metadaten. Der Configuration Manager liefert geänderte SMTP-Einstellungen, ohne dass der Mail-Dienst neu gestartet werden muss.

Fehler werden als strukturierte Antwort unter `error.message` zurückgegeben; einzelne Antworten können außerdem `code` und `details` enthalten. Geben Sie SMTP-Zugangsdaten, Token und Einmalcodes weder in öffentlichen Protokollen noch in Support-Nachrichten weiter. Bei einer fehlenden Konfiguration, ungültigen Vorlage, ungültiger Empfängeradresse oder einem SMTP-Fehler prüfen Sie den jeweiligen Schritt, bevor Sie den Versand erneut auslösen.
