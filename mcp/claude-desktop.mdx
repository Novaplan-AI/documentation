Claude Desktop can talk to the Novaplan AI MCP server, but there's one important catch to understand before you start.

<Warning>
  **Claude Desktop does not support local HTTP MCP transport.** Unlike a server-side tool, it won't connect to a plain `http://localhost:.../mcp` endpoint. To connect Novaplan AI you have two options, and which one you pick depends on how Novaplan AI is hosted:

  1. **Add it as a custom connector** — works only when Novaplan AI is reachable over **public HTTPS** (a real domain with a valid SSL certificate), exactly like [Claude.ai (Web)](/mcp/claude-ai).
  2. **Run a local stdio bridge** — for a workspace reachable only on an internal network, using the `@pipeshub-ai/mcp` npm package and a personal access token. Confirm package suitability with Novaplan before using this route.
</Warning>

<Tip>
  Use the workspace endpoint supplied by your administrator. If you need access, contact [Novaplan AI support](/contact-us). Do not point Claude Desktop's custom connector at localhost.
</Tip>

## Which option should I use?

| Your situation | Use this |
|---|---|
| Your workspace has a public HTTPS address (e.g. `https://your-workspace.example.com`) | [Custom connector](#option-1-custom-connector-hosted-novaplan-ai) |
| Your workspace is available only on an internal network | [Local stdio bridge](#option-2-local-stdio-bridge), subject to Novaplan verification |

## Option 1: Custom connector (hosted Novaplan AI)

If your Novaplan AI instance is served over HTTPS on a valid domain reachable from Anthropic's cloud, Claude Desktop can use a remote custom connector — no local npm package is needed. Remote connectors are configured through your Claude account and also appear in Claude Desktop. See the [Claude.ai guide](/mcp/claude-ai) and [Anthropic's current instructions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

<Note>
  Before you start, create an OAuth app in Novaplan AI and note your **Client ID** and **Client Secret**. See [MCP Server Overview](/mcp/overview#step-1-create-an-oauth-app).
</Note>

<Steps>
  <Step title="Open Connectors settings">
    In Claude Desktop or [Claude.ai](https://claude.ai), open **Customize → Connectors** for an individual account. For a Team or Enterprise organization, an Owner first adds the connector under **Organization settings → Connectors**.
  </Step>
  <Step title="Add a custom connector">
    For an individual account, click **+** and then **Add custom connector**. For an organization, choose **Add → Custom → Web**.
  </Step>
  <Step title="Enter the MCP server URL">
    Use your public HTTPS instance URL with the `/mcp` path:
    ```
    NOVAPLAN_WORKSPACE_URL/mcp
    ```
    For example: `https://your-workspace.example.com/mcp`.
  </Step>
  <Step title="Enter OAuth credentials">
    Click **Advanced settings** and enter your OAuth credentials:
    - **OAuth Client ID**: `YOUR_CLIENT_ID`
    - **OAuth Client Secret**: `YOUR_CLIENT_SECRET`
  </Step>
  <Step title="Add and authenticate">
    Click **Add**, then **Connect** if prompted. Complete the Novaplan AI sign-in and review the requested permissions. Once connected, the connector is available through your Claude account, including in Claude Desktop.
  </Step>
</Steps>

### Redirect URI

Claude Desktop uses the same OAuth callback as the Claude web app:

```
https://claude.ai/api/mcp/auth_callback
```

Register this as an allowed redirect URI in your Novaplan AI OAuth app, and confirm the callback used in the live Claude connector flow before deployment.

<Note>
  A custom connector needs the workspace to be reachable from the public internet over HTTPS. If it is internal-only, ask Novaplan whether the local bridge is approved for your environment.
</Note>

## Option 2: Local stdio bridge

For an internal-only workspace, Claude Desktop can launch a local **stdio process** that connects to its remote API. The existing bridge package is `@pipeshub-ai/mcp`; Novaplan must confirm that this package is supported for the Enterprise workspace before customers use it.

### Prerequisites

- Node.js 20+ installed
- The workspace URL supplied by Novaplan
- A personal access token for the person using Claude Desktop

<Warning>
  Do not use a **Client Credentials** token for permissioned company search. That grant has no user identity. Use the person's token and confirm with Novaplan that the bridge is supported. Do not store the token in a shared or committed config file.
</Warning>

### Configuration

Open Claude Desktop's config file (`claude_desktop_config.json`) and add the Novaplan AI server. You can find it via **Settings > Developer > Edit Config**, or at:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "novaplan": {
      "command": "npx",
      "args": [
        "-y",
        "@pipeshub-ai/mcp",
        "start",
        "--server-url",
        "NOVAPLAN_WORKSPACE_URL",
        "--bearer-auth",
        "YOUR_BEARER_TOKEN"
      ]
    }
  }
}
```

Replace the placeholders with the approved workspace origin and the person's token. Use a local secret-management method for the token rather than committing this example with real credentials.

### Apply the changes

Save the file and **fully quit and reopen Claude Desktop** (a window reload isn't enough). Once it restarts, the Novaplan AI tools appear under the tools menu in your conversations.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The custom connector won't connect / shows an error">
    Custom connectors require a **public HTTPS** endpoint with a valid SSL certificate. Claude Desktop cannot reach private hostnames through this connector flow. Ask Novaplan for the approved workspace endpoint or whether the [local stdio bridge](#option-2-local-stdio-bridge) is supported.
  </Accordion>
  <Accordion title="The stdio server doesn't start">
    - Make sure Node.js 20+ is installed and `npx` is on your `PATH`.
    - Confirm your approved workspace endpoint is reachable from the computer running Claude Desktop.
    - After editing `claude_desktop_config.json`, fully quit and relaunch Claude Desktop.
  </Accordion>
  <Accordion title="Authentication fails on the stdio bridge">
    Verify the personal token is valid, belongs to the intended user, has the required scopes, and is passed to `--bearer-auth`. If the package is not supported in your Enterprise workspace, contact Novaplan Support.
  </Accordion>
</AccordionGroup>
