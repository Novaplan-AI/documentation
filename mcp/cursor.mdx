Cursor supports static OAuth for remote MCP servers via the `auth` object in `mcp.json`.

<Note>
  Before you start, create an OAuth app in Novaplan AI and note your **Client ID** and **Client Secret**. See [MCP Server Overview](/mcp/overview#step-1-create-an-oauth-app).
</Note>

<Tip>
  Coding agents: read [For coding agents](/for-agents) first. If they do not have workspace access yet, contact [Novaplan AI support](/contact-us). MCP configuration and repository instructions are separate setup steps.
</Tip>

## Configuration

Open **Cursor Settings > Tools and Integrations > New MCP Server**, or edit your project's `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "novaplan": {
      "url": "NOVAPLAN_WORKSPACE_URL/mcp",
      "auth": {
        "CLIENT_ID": "YOUR_CLIENT_ID",
        "CLIENT_SECRET": "YOUR_CLIENT_SECRET",
        "scopes": [
          "openid", "profile", "email", "offline_access",
          "semantic:write",
          "conversation:write", "conversation:chat",
          "kb:read", "team:read", "user:read", "config:read"
        ]
      }
    }
  }
}
```

Cursor discovers the OAuth endpoints from Novaplan AI's metadata.

<Note>
  If `scopes` is omitted, Cursor's current documentation says it reads `scopes_supported` from `/.well-known/oauth-authorization-server`. To limit access, list only the scopes approved for the tools you need. See [Customizing Default Scopes](/mcp/overview#customizing-default-scopes) if Novaplan's server-side defaults need review.
</Note>

## Using Environment Variables

Use Cursor's `${env:VAR}` interpolation to keep secrets out of config files:

```json
{
  "mcpServers": {
    "novaplan": {
      "url": "${env:NOVAPLAN_WORKSPACE_URL}/mcp",
      "auth": {
        "CLIENT_ID": "${env:NOVAPLAN_CLIENT_ID}",
        "CLIENT_SECRET": "${env:NOVAPLAN_CLIENT_SECRET}",
        "scopes": [
          "openid", "profile", "email", "offline_access",
          "semantic:write",
          "conversation:write", "conversation:chat",
          "kb:read", "team:read", "user:read", "config:read"
        ]
      }
    }
  }
}
```

## Redirect URIs

Register the callback URI for each Cursor surface your team uses in the Novaplan OAuth app:

| Cursor surface | Redirect URI |
| --- | --- |
| Desktop app (current) | `http://localhost:8787/callback` |
| Desktop app (older installations) | `cursor://anysphere.cursor-mcp/oauth/callback` |
| Web and Cursor Agents | `https://www.cursor.com/agents/mcp/oauth/callback` |

Cursor's current [MCP documentation](https://cursor.com/docs/mcp#static-redirect-url) lists the localhost callback for the desktop app and the HTTPS callback for web/agents. Some older desktop installations still use the `cursor://` callback. The accessible Novaplan OAuth source accepts that legacy URI as well as localhost and HTTPS redirects, but the deployed Enterprise app still needs a sign-in test. A redirect mismatch means the exact URI sent by Cursor is not registered; check the authorization request before changing the OAuth app.

## OAuth Login Troubleshooting

If Cursor's internal browser fails to load the OAuth login page, copy the authorization URL from the internal browser and paste it into your normal browser to complete the login flow.
