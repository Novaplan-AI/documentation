Claude Code can connect to Novaplan AI's remote HTTP MCP endpoint with a **personal access token** for an individual's own client, or with an **OAuth app** for a shared or administrator-managed setup. No local stdio bridge is needed for either remote connection.

The instructions below use the actual MCP URL ending in `/mcp`. The `/api/v1` base URL belongs only to the optional [local stdio bridge](/mcp/local-server).

<Note>
  Confirm that personal access tokens and the MCP endpoint are enabled in your managed workspace before connecting. A PAT is bound to the user who created it and is limited by that user's permissions and the token's scopes. See [Personal Access Tokens](/developer/personal-access-tokens).
</Note>

<Tip>
  Coding agents: read [For coding agents](/for-agents) first. If they do not have workspace access yet, contact [Novaplan AI support](/contact-us). MCP configuration and repository instructions are separate setup steps.
</Tip>

## Connect with your personal access token

1. In **Developer Settings → Personal Access Tokens**, create a token for your own account with the required scopes. Copy the MCP URL and token from the one-time paste block into a local secret store or environment variables named `PIPESHUB_MCP_URL` and `PIPESHUB_MCP_TOKEN`. These names are functional identifiers used by the current token flow. The URL already ends in `/mcp`.
2. In your project, add a `.mcp.json` file with environment-variable references rather than a literal token:

```json
{
  "mcpServers": {
    "novaplan": {
      "type": "http",
      "url": "${PIPESHUB_MCP_URL}",
      "headers": {
        "Authorization": "Bearer ${PIPESHUB_MCP_TOKEN}"
      }
    }
  }
}
```

3. Run `claude mcp list` and test a query that your account is allowed to answer. Claude Code [expands environment variables in remote server URLs and headers](https://code.claude.com/docs/en/mcp#environment-variable-expansion-in-mcpjson). Make sure both variables exist in the environment where Claude Code starts.

For a remote workspace, use an **HTTPS** MCP URL because each request carries a bearer token. Never commit the token or put its literal value in a project configuration. Revoke a leaked token under **Personal Access Tokens**.

## Connect with an OAuth app

For shared or administrator-managed OAuth setup, create an OAuth app in Novaplan AI and note your **Client ID** and **Client Secret**. See [MCP Server Overview](/mcp/overview#step-1-create-an-oauth-app). Novaplan AI exposes discovery at `/.well-known/oauth-protected-resource/mcp`, so Claude Code discovers the authorization and token endpoints.

<Note>
  Claude Code can request an approved subset of OAuth scopes through `oauth.scopes` in its server configuration. Without that setting, current Claude Code versions use the scope from the server's authentication challenge or protected-resource metadata, if provided. The OAuth app must permit the scopes actually requested. See [Customizing Default Scopes](/mcp/overview#customizing-default-scopes) if the server's advertised defaults need review.
</Note>

### Add with CLI

```bash
claude mcp add --transport http \
  --client-id YOUR_CLIENT_ID \
  --client-secret \
  --callback-port 8080 \
  novaplan NOVAPLAN_WORKSPACE_URL/mcp
```

<Note>
  `--client-secret` without a value prompts for masked input. To skip the prompt, set the `MCP_CLIENT_SECRET` environment variable:

  ```bash
  MCP_CLIENT_SECRET=YOUR_CLIENT_SECRET claude mcp add --transport http \
    --client-id YOUR_CLIENT_ID \
    --client-secret \
    --callback-port 8080 \
    novaplan NOVAPLAN_WORKSPACE_URL/mcp
  ```
</Note>

To make it available across all projects:

```bash
claude mcp add --transport http --scope user \
  --client-id YOUR_CLIENT_ID \
  --client-secret \
  --callback-port 8080 \
  novaplan NOVAPLAN_WORKSPACE_URL/mcp
```

### Add with JSON

```bash
claude mcp add-json novaplan '{
  "type": "http",
  "url": "NOVAPLAN_WORKSPACE_URL/mcp",
  "oauth": {
    "clientId": "YOUR_CLIENT_ID",
    "callbackPort": 8080
  }
}' --client-secret
```

### Project-scoped configuration

From the project root, add `--scope project` to the CLI command. Claude Code writes the non-secret server configuration to `.mcp.json`; review that file before committing it. Each team member still needs access to the Novaplan workspace and must authenticate individually.

```bash
claude mcp add --transport http --scope project \
  --client-id YOUR_CLIENT_ID \
  --client-secret \
  --callback-port 8080 \
  novaplan NOVAPLAN_WORKSPACE_URL/mcp
```

The client secret is requested **when the server is added** and kept outside `.mcp.json` by Claude Code. Its storage depends on the operating system; do not put it in a committed configuration file. To pin a narrower set of scopes, set `oauth.scopes` in the server's JSON configuration to a single space-separated string of scopes approved for the intended tools, then re-authenticate. See [Claude Code's MCP documentation](https://code.claude.com/docs/en/mcp#restrict-oauth-scopes) for the current format.

### Authenticate

After adding the server, run `/mcp` inside Claude Code and follow the browser login flow. Tokens are stored securely and refreshed automatically.

## Verify

```bash
claude mcp list
claude mcp get novaplan
```
