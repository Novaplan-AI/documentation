Instead of connecting to Novaplan AI's remote MCP endpoint directly, you may be able to run a local stdio bridge using the existing `@pipeshub-ai/mcp` npm package. Novaplan must confirm that this package is supported for your Enterprise workspace before you use it. Prefer the remote MCP endpoint when your client supports it.

<Warning>
  Permissioned company search needs a **user-bound** credential. Use a personal access token for this bridge. OAuth `client_credentials` does not represent a user and must not be used to retrieve content under a person's Novaplan AI access rights.
</Warning>

## Prerequisites

- Node.js 20+ installed
- A Novaplan AI workspace URL and its API base URL ending in `/api/v1`
- A **[Personal Access Token](/developer/personal-access-tokens)** belonging to the person using the client

<Tip>
  No workspace access yet? Contact [Novaplan AI support](/contact-us) before configuring the bridge.
</Tip>

<Tip>
  For the `--bearer-auth` flag used throughout this page, a [Personal Access Token](/developer/personal-access-tokens) is the easiest option: create one under **Developer Settings > Personal Access Tokens** and use it directly — no OAuth app, redirect URIs, or token exchange required.
</Tip>

## Placeholders

Replace these in all configurations below:

| Placeholder | Description | Example |
|---|---|---|
| `NOVAPLAN_API_URL` | Your Novaplan AI workspace URL followed by `/api/v1` for this local bridge | `https://your-workspace.example.com/api/v1` |
| `YOUR_BEARER_TOKEN` | [Personal access token](/developer/personal-access-tokens) (or any other Bearer JWT) | `phpat_eyJhbGci...` |

The local bridge's `--server-url` uses the **API base URL**. A client connecting directly over remote HTTP instead uses `NOVAPLAN_WORKSPACE_URL/mcp`; do not append `/api/v1` to that remote MCP URL. Confirm the bridge package and endpoint against your managed workspace with Novaplan before relying on the connection.

## Claude Desktop

Claude Desktop has its own dedicated guide, since it can't connect to a local HTTP MCP endpoint and needs either a custom connector (hosted) or this stdio bridge. See [Claude Desktop](/mcp/claude-desktop) for the full setup.

## Cursor

Open **Cursor Settings > Tools and Integrations > New MCP Server**, or edit your project's `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "novaplan": {
      "command": "npx",
      "args": [
        "-y",
        "@pipeshub-ai/mcp",
        "start",
        "--server-url",
        "NOVAPLAN_API_URL",
        "--bearer-auth",
        "YOUR_BEARER_TOKEN"
      ]
    }
  }
}
```

## Retries and timeouts

The current `@pipeshub-ai/mcp` bridge retries safe-to-repeat requests that receive 429, 502, 503, or 504, up to three attempts. It follows a `Retry-After` delay of at most 30 seconds; without one it uses a short increasing delay. It retries GET, HEAD, OPTIONS, PUT, and DELETE, but not POST searches or chat requests. Each attempt waits up to 60 seconds for the server to start responding. A response that has started streaming is not cut off by that limit.

Set these environment variables in your MCP client's `env` block if the bridge needs different limits:

| Variable | Default | Allowed values |
| --- | --- | --- |
| `PIPESHUB_MCP_MAX_ATTEMPTS` | `3` | Integer from 1 to 10; `1` disables retries |
| `PIPESHUB_MCP_TIMEOUT_MS` | `60000` | Milliseconds up to 3,600,000; `0` disables the timeout |

This is behavior of the technical package and still needs confirmation against the managed Enterprise workspace. A timeout or network error should prompt a check of `--server-url`, workspace health, and certificate trust.
