# DeepSeek configuration

![OpenAI-compatible model configuration in Novaplan AI](/images/ai-models/llm/OpenAICompatible_LLMConfig.png)

DeepSeek provides an OpenAI-compatible API that Novaplan AI can use for a language model. Novaplan helps connect it to your managed workspace. You need a DeepSeek account, an API key, an approved model, and network access from the Novaplan environment to DeepSeek.

<Warning>
  DeepSeek retired the older `deepseek-chat` and `deepseek-reasoner` API model names in July 2026. Do not copy those IDs from an older setup guide. Check DeepSeek's [current model list](https://api-docs.deepseek.com/quick_start/pricing/) before configuring or renewing the connection. The model and optional features must also be tested with the deployed Novaplan AI version.
</Warning>

## Required fields

| Field | What to enter |
| --- | --- |
| **Provider Type** | **OpenAI API Compatible** |
| **Endpoint URL** | DeepSeek's documented OpenAI-format base URL: `https://api.deepseek.com`. Confirm the exact value accepted by your Novaplan workspace before saving; older examples in this guide used `/v1/`. |
| **API Key** | A key created in the [DeepSeek Platform](https://platform.deepseek.com). Store it only in the approved model configuration. |
| **Model Name** | The exact current API model ID. DeepSeek's current documentation uses `deepseek-flash`; verify availability in your account and region. |

The Endpoint URL, API Key, and Model Name fields are required by the Novaplan form. DeepSeek's published base URL does not include `/v1/`; do not assume the suffix is required just because the provider option is named **OpenAI API Compatible**. Novaplan should test the endpoint from the managed workspace before customers depend on it.

To obtain a key, sign in to the DeepSeek Platform, open **API Keys**, create a key, and copy it immediately. Ask your administrator to confirm billing, allowed data use, and the model choice. Never place the key in documentation, screenshots, chats, or source code.

## Optional features

DeepSeek's current `deepseek-flash` API supports image input and thinking mode according to its [API reference](https://api-docs.deepseek.com/api/create-chat-completion/) and [thinking-mode guide](https://api-docs.deepseek.com/guides/thinking_mode/). Enable **Multimodal** only after Novaplan confirms that the deployed integration sends image inputs in a supported format. The **Reasoning** checkbox should likewise be tested: DeepSeek exposes a separate thinking control, and the checkbox alone does not prove how Novaplan sends it.

Model features and names change. Check the current DeepSeek documentation and the chosen model's capabilities whenever you change the configuration.

## Connect the model

1. In Novaplan AI, choose **OpenAI API Compatible** as the provider type.
2. Enter the DeepSeek **Endpoint URL**, **API Key**, and exact **Model Name** agreed with Novaplan.
3. Set **Multimodal** and **Reasoning** only after testing the selected model and deployed Novaplan integration.
4. Click **Add Model** and run a permitted text test. If image or thinking behavior matters, test those separately.

If connection fails, check the base URL, network access from the managed workspace, API key, account balance, model ID, and DeepSeek's current API status. For image or thinking errors, compare the request behavior with DeepSeek's current API reference. Contact [Novaplan Support](/contact-us) for integration-specific help.
